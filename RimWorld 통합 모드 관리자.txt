# RimWorld 통합 모드 관리자
## 기능 및 UI 설계 제안서

## 1. 프로젝트 개요

기존 RimWorld의 바닐라 모드 관리 화면을 대체하는 독립적인 모드 관리 시스템을 제작한다.

모드를 카테고리, 폴더, 태그로 분류하고, 드래그 앤 드롭, 다중 선택, 일괄 활성화, 자체 정렬, 프리셋 저장 등의 기능을 제공한다.

모드 식별은 `PackageId`를 기준으로 하며, 구독 상태와 별개로 사용자 관리 데이터를 유지한다.

## 2. 기본 화면 구성

### 2-1. 화면 진입

- 메인 화면의 기존 모드 버튼을 누르면 새 모드 관리자 화면을 표시한다.
- 기존 바닐라 모드 관리 화면을 대체한다.
- 게임 화면 전체 크기를 사용한다.
- 외부 Padding은 0으로 설정한다.
- 배경은 안보이게 검정으로 채우기.

### 2-2. 전체 레이아웃

화면을 상하 및 좌우로 분할한다.

- 상단 영역: 화면 높이에서 하단 버튼 영역 30px를 제외한 전체.
- 하단 영역: 높이 30px.
- 상단 좌측: 전체 너비의 약 2/3.
- 상단 우측: 전체 너비의 약 1/3.

좌측에는 카테고리 또는 태그 관리 화면을 표시하고, 우측에는 선택한 모드의 상세 정보를 표시한다.

### 2-3. UI 크기 기준

| 항목 | 크기 |
|---|---:|
| 하단 버튼 영역 | 30px |
| 기본 버튼 높이 | 24px |
| 모드 목록 항목 | 27px |
| 카테고리/태그 헤더 | 60px |
| 헤더 이름 영역 | 30px |
| 헤더 기능 버튼 영역 | 30px |

모든 버튼에 툴팁을 제공한다.

## 3. 모드 목록 공통 기능

### 3-1. 모드 식별 및 표시

- 모드의 고유 식별자는 `PackageId`로 한다.
- 바닐라 모드 이름과 사용자 지정 표시 이름을 별도로 관리한다.
- 사용자 지정 표시 이름이 있으면 해당 이름을 표시한다.
- 사용자 지정 표시 이름이 없으면 바닐라 이름을 사용한다.
- 사용자 지정 표시 이름은 실제 모드 정보에 영향을 주지 않는다.
- 미구독 모드도 관리 목록에 유지한다.
- 미구독 모드는 Steam 아이콘 대신 별도의 아이콘을 표시한다.

### 3-2. 선택 기능

- 일반 클릭: 단일 선택.
- Ctrl + 클릭: 개별 항목 추가 선택 및 선택 해제.
- Shift + 클릭: 마지막 선택 위치부터 현재 위치까지 범위 선택.
- Ctrl + A: 현재 목록 전체 선택.
- 다중 선택 상태에서 일괄 이동, 활성화, 비활성화 가능.

### 3-3. 드래그 앤 드롭

다음 작업을 지원한다.

- 모드 목록 순서 변경.
- 모드를 다른 카테고리로 이동.
- 모드를 다른 폴더로 이동.
- 모드를 다른 태그에 추가하거나 태그 폴더로 이동.
- 여러 모드를 한 번에 이동.

드래그 대상과 이동 가능 위치를 시각적으로 구분한다.

### 3-4. 우클릭 메뉴

모드 항목을 우클릭하면 다음 메뉴를 표시한다.

1. 카테고리 이동
2. 폴더 이동/추가
3. 태그 추가
4. 태그 제거
5. 표시 이름 변경
6. 기본 이름으로 초기화
7. 선택 항목 활성화
8. 선택 항목 비활성화
9. 모드 설명 보기
10. Workshop 페이지 열기
11. PackageId 복사
12. 모드 폴더 열기

다중 선택 상태에서 우클릭하면 선택된 모드 전체에 적용한다.

### 3-5. 검색 및 필터

검색 대상:

- 바닐라 모드 이름
- 사용자 표시 이름
- PackageId
- 제작자
- 설명
- 태그
- 카테고리

검색 결과에 해당하는 항목만 표시한다.

필터:

- 전체
- 활성화
- 비활성화
- 구독 중
- 미구독
- 태그 미부여
- 카테고리 미분류

## 4. 모드 활성화 및 비활성화 규칙

### 4-1. 기본 원칙

실제 모드의 개별 활성화 상태는 PackageId별로 하나만 관리한다.

최종 게임 적용 여부는 카테고리 상태와 모드 개별 상태만으로 결정한다.

**최종 적용 조건:**

`카테고리 활성화 AND 모드 개별 활성화`

- 카테고리가 비활성화되면 해당 카테고리의 모드는 최종 적용 대상에서 제외한다.
- 카테고리가 활성화되어 있으면 모드 개별 활성화 상태를 따른다.
- 태그와 폴더 자체는 최종 적용 여부를 결정하지 않는다.

### 4-2. Core 및 DLC 보호

Core와 DLC는 필수 모드로 취급한다.

- 개별 비활성화 버튼 사용 불가.
- 카테고리 비활성화의 영향을 받지 않음.
- 태그 및 폴더 일괄 변경 대상에서 제외.
- 필수 로드 위치 유지.

### 4-3. 태그 및 폴더의 활성화 기능

태그와 폴더는 별도의 활성화 상태를 저장하지 않는다.

소속된 모드의 개별 활성화 상태를 집계해 표시한다.

| 표시 | 상태 | 의미 |
|---|---|---|
| ● | 활성 | 소속 모드 전부 활성화 |
| ○ | 비활성 | 소속 모드 전부 비활성화 |
| ◐ | 혼합 | 활성화 및 비활성화 모드가 함께 존재 |

클릭 동작:

- ● 클릭 → 전체 비활성화
- ○ 클릭 → 전체 활성화
- ◐ 클릭 → 전체 활성화

Core 및 DLC는 일괄 변경에서 제외한다.

한 태그에서 모드 상태를 변경하면 동일한 모드가 표시되는 다른 태그 및 카테고리 화면에도 즉시 반영한다.

## 5. 카테고리 관리

### 5-1. 기본 카테고리

최초 실행 시 다음 4개 카테고리를 생성한다.

1. 선행 모드
2. 핵심 모드
3. 일반 모드
4. 후순위 모드

초기 분류:

- Core/DLC보다 먼저 로드되는 모드 → 선행 모드
- Core/DLC → 핵심 모드
- Core/DLC 이후 로드되는 모드 → 일반 모드
- 후순위 모드 → 비워 둠

초기 태그는 생성하지 않는다.

각 카테고리에는 기본 폴더인 `미분류`를 생성하고, 펼쳐진 상태로 시작한다. 신규 모드는 해당 카테고리의 미분류 폴더에 배치한다.

### 5-2. 카테고리 목록 UI

카테고리 목록은 가로 방향으로 배치한다.

- 10개 이상의 카테고리를 표시할 수 있도록 가로 스크롤 지원.
- 드래그 앤 드롭으로 순서 변경.
- 좌우 이웃과 위치 교체 가능.
- 카테고리 이름 직접 수정 가능.
- 이름 중복 불가.

헤더 구성:

- 상단 30px: 카테고리 이름.
- 하단 30px: 기능 버튼.

기능 버튼 순서:

`+  <  >  활성/비활성  X  +`

기능:

- 왼쪽 추가: 왼쪽에 카테고리 생성.
- 왼쪽 교체: 왼쪽 카테고리와 위치 교체.
- 오른쪽 교체: 오른쪽 카테고리와 위치 교체.
- 활성/비활성: 카테고리 활성 상태 변경.
- 삭제: 카테고리 삭제.
- 오른쪽 추가: 오른쪽에 카테고리 생성.

카테고리 삭제는 내부에 모드가 없을 때만 허용한다.

검색어가 입력되면 검색 결과가 포함된 카테고리만 표시한다.

### 5-3. 카테고리 관리 화면 하단 버튼

왼쪽부터 다음 순서로 배치한다.

1. 태그 모드
2. 카테고리 추가
3. 구독 취소
4. 폴더 바로가기
5. 모드 목록 저장
6. 모드 목록 불러오기
7. 변경사항 취소
8. 변경사항 적용

### 5-4. 카테고리 내부 모드 목록

- 세로 방향 목록.
- 세로 스크롤 지원.
- 모드 항목 높이 27px.
- 폴더별로 모드를 구분하여 표시.
- 기본 미분류 폴더는 펼친 상태.

폴더 우클릭 메뉴:

1. 폴더 이름 변경
2. 폴더 활성화/비활성화
3. 폴더 추가
4. 폴더 삭제
5. 전체 모드 선택
6. 접기/펼치기

폴더 활성화/비활성화는 폴더에 포함된 모드의 개별 활성화 상태를 일괄 변경한다.

## 6. 태그 관리

### 6-1. 태그 기본 기능

모드 하나에 여러 태그를 부여할 수 있다.

태그 목록은 가로 방향으로 표시한다.

- 10개 이상 표시할 수 있도록 가로 스크롤 지원.
- 드래그 앤 드롭으로 순서 변경.
- 좌우 이웃과 위치 교체 가능.
- 태그 이름 직접 수정 가능.
- 태그 이름 중복 불가.

카테고리와 마찬가지로 헤더 높이는 60px이며, 기능 버튼은 다음과 같다.

`+  <  >  활성/비활성  X  +`

태그 삭제는 내부에 모드가 있어도 가능하다. 삭제 시 모든 모드에서 해당 태그 연결을 해제하고 확인창을 표시한다.

### 6-2. 태그 관리 화면 하단 버튼

1. 카테고리 모드
2. 태그 추가
3. 구독 취소
4. 폴더 바로가기
5. 모드 목록 저장
6. 모드 목록 불러오기
7. 변경사항 취소
8. 변경사항 적용

### 6-3. 태그 내부 모드 목록

각 태그에 해당 태그가 부여된 모드만 표시한다.

태그 내부에도 폴더 기능을 제공한다.

- 폴더 생성 및 삭제.
- 폴더 이름 변경.
- 폴더 순서 변경.
- 접기 및 펼치기.
- 모드 이동.
- 폴더 단위 모드 선택.
- 폴더 단위 활성화 및 비활성화.

태그 내부 폴더는 태그마다 독립적으로 관리한다.

태그 폴더 사이에서 모드를 이동해도 태그 연결 자체는 변경하지 않는다.

태그 추가 팝업:

- 이름 입력.
- 확인 및 취소.
- Enter로 생성.
- 동일한 이름의 태그가 이미 존재하면 새로 생성하지 않고 기존 태그를 사용한다.

## 7. 폴더 관리

### 7-1. 폴더 기본 규칙

- 카테고리마다 독립적인 폴더 목록을 가진다.
- 태그마다 독립적인 폴더 목록을 가진다.
- 기본 폴더 이름은 미분류.
- 신규 모드는 미분류에 배치.
- 폴더 이름 중복 불가.
- 폴더 순서 변경 가능.
- 폴더 접기 및 펼치기 가능.

카테고리 폴더와 태그 폴더는 별도의 데이터로 관리한다.

하나의 모드가 여러 태그에 속할 수 있으므로, 같은 모드가 서로 다른 태그의 폴더 목록에 각각 표시될 수 있다. 다만 모드의 개별 활성화 상태는 PackageId 기준으로 공유한다.

### 7-2. 폴더 이동/추가 팝업

모드 우클릭 메뉴에서 `폴더 이동/추가`를 선택하면 별도 팝업을 표시한다.

팝업 구성:

- 현재 모드가 속한 카테고리 또는 태그 표시.
- 해당 영역의 폴더 목록.
- 새 폴더 이름 입력란.
- 확인 및 취소 버튼.

동작:

- 기존 폴더를 선택하면 해당 폴더로 이동.
- 새 이름을 입력하면 폴더 생성 후 이동.
- Enter 키로 생성 또는 이동.
- 현재 영역에서 폴더 이름 중복 불가.
- 다중 선택 시 선택된 모드를 모두 이동.

다른 카테고리의 폴더로 이동할 때 동일한 이름의 폴더가 있으면 기존 폴더에 병합한다.

병합 시 내부 모드를 기존 폴더로 이동하며, 가능한 한 기존 모드 순서를 유지한다.

## 8. 빠른 폴더 이동 창

### 8-1. 기본 설계

하단 버튼의 `구독 취소` 오른쪽에 `폴더 바로가기` 버튼을 배치한다.

이 버튼을 누르면 별도의 팝업 창을 표시한다.

**중요: 기존의 모드 목록과 폴더 목록을 따로 배치하는 2열 방식이 아니라, 3열 구조로 구성한다.**

창을 열었을 때 세 개의 목록 영역과 각 목록의 항목이 한 화면에 최대한 모두 보이도록 한다.

### 8-2. UI 배치

```text
┌──────────────────────────────────────────────┐
│       목록 1       │       목록 2       │ 목록 3 │
├────────────────────┼────────────────────┼────────┤
│ 폴더 1             │ 폴더 2             │ 폴더 1 │
│ 폴더 2             │ 폴더 3             │ 폴더 3 │
│ 폴더 3             │                    │ 폴더 4 │
│ 폴더 4             │                    │        │
│                    │                    │        │
└────────────────────┴────────────────────┴────────┘
```

실제 목록 이름은 현재 관리 모드에 맞게 표시한다.

- 카테고리 관리 화면: 카테고리별 폴더 목록.
- 태그 관리 화면: 태그별 폴더 목록.

### 8-3. 3개 목록의 역할

- 목록 1: 첫 번째 카테고리 또는 태그의 폴더 목록.
- 목록 2: 두 번째 카테고리 또는 태그의 폴더 목록.
- 목록 3: 세 번째 카테고리 또는 태그의 폴더 목록.

각 목록은 서로 독립적으로 표시한다.

카테고리나 태그가 3개를 초과하는 경우에는 다음과 같이 처리한다.

- 화면에 표시할 세 목록을 좌우로 이동해 선택할 수 있도록 한다.
- 각 목록은 해당 카테고리 또는 태그의 폴더를 표시한다.
- 목록 내부는 세로 스크롤을 지원한다.
- 목록의 제목에는 해당 카테고리 또는 태그 이름을 표시한다.

각 목록에는 폴더 이름을 세로로 나열한다.

### 8-4. 이동 방법

1. 모드 목록에서 이동할 모드를 선택한다.
2. 여러 모드를 동시에 선택할 수 있다.
3. 세 목록 중 원하는 폴더를 클릭한다.
4. 선택한 모드들이 해당 폴더로 이동한다.
5. 이동 결과는 기존 카테고리/태그 관리 화면에도 즉시 반영한다.

카테고리 관리에서는 모드의 카테고리 폴더 배치를 변경한다.

태그 관리에서는 해당 태그 내부의 폴더 배치만 변경한다. 모드의 태그 연결 자체는 변경하지 않는다.

### 8-5. 추가 편의 기능

- 폴더 검색.
- 즐겨찾기 폴더.
- 최근 사용 폴더.
- 현재 선택된 폴더 강조 표시.
- 폴더에 들어 있는 모드 수 표시.
- 모드 다중 선택.
- 이동 후 목록 자동 갱신.
- 현재 화면과 관계없이 언제든지 실행 가능.

## 9. 모드 정보 영역

우측 영역은 바닐라 모드 정보 화면을 기반으로 개조한다.

표시 순서:

1. 사용자 지정 표시 이름.
2. 기존 바닐라 모드 이름.
3. 모드 버전.
4. 태그 목록.
5. PackageId.
6. 제작자.
7. 지원 게임 버전.
8. 모드 설명.
9. Workshop 페이지.
10. 선행 모드 목록.

태그 표시 예시:

`태그: [태그 A] [태그 B] [+]`

태그 기능:

- 태그 클릭: 해당 태그 관리 화면으로 이동.
- 태그 우클릭: 해당 모드에서 태그 제거.
- + 버튼 클릭: 태그 추가 팝업 표시.

## 10. 바닐라 기능 연동 및 자체 정렬

### 10-1. 바닐라 기능 연동

- 바닐라의 선행 모드 경고 기능을 사용한다.
- 바닐라의 자동 정렬 버튼을 누르면 모드 관리자의 자체 정렬 시스템을 실행한다.

### 10-2. 자체 정렬 우선순위

1. 선행 모드 의존성.
2. Core 및 DLC 필수 위치.
3. 카테고리 순서.
4. 폴더 순서.
5. 폴더 내부 모드 사용자 지정 순서.

의존성 조건을 만족하는 범위에서 사용자가 지정한 순서를 최대한 유지한다.

정렬 결과는 실제 게임 모드 목록과 관리자 데이터에 모두 반영한다.

## 11. 구독 취소 및 모드 목록 관리

### 11-1. 구독 취소

- 선택한 모드의 Steam 구독 취소.
- 다중 선택 후 일괄 구독 취소.
- 실행 전 확인창 표시.

구독 취소 후에도 다음 관리 데이터는 유지한다.

- PackageId.
- 사용자 표시 이름.
- 카테고리.
- 폴더.
- 태그.
- 순서.
- 프리셋 정보.

미구독 모드도 관리 목록에서 제거하지 않는다.

### 11-2. 관리 목록에서 제거

구독 취소와 별도로 모드를 관리 목록에서 제거하는 기능을 제공한다.

- 활성화된 모드는 제거 전 경고 또는 차단.
- 비활성화된 모드는 제거 가능.
- 실제 모드 폴더 삭제는 사용자 확인 후 실행.
- Steam 다운로드 상태와 게임 사용 상태 확인.
- 삭제 전 관련 데이터 정리 여부를 확인한다.

## 12. 저장 및 불러오기

ModSettings와 Scribe를 이용한다.

### 12-1. 저장 데이터

- 카테고리 목록 및 순서.
- 카테고리 활성 상태.
- 모드별 카테고리 배치.
- 카테고리별 폴더 목록 및 순서.
- 모드별 폴더 배치.
- 모드별 개별 활성화 상태.
- 사용자 지정 표시 이름.
- 태그 목록 및 순서.
- 모드별 태그 연결.
- 태그별 폴더 목록 및 순서.
- 폴더 접기 및 펼치기 상태.
- 즐겨찾기 및 최근 사용 폴더.

태그와 폴더의 활성화 표시는 소속 모드의 개별 활성화 상태를 집계하여 계산한다.

### 12-2. 프리셋

프리셋 저장 항목:

- 카테고리.
- 폴더.
- 모드 배치.
- 개별 활성화 상태.
- 태그.
- 태그 연결.
- 사용자 표시 이름.

프리셋 불러오기 시 미구독 모드를 표시하고, 미구독 모드의 관리 정보도 유지한다.

### 12-3. 변경사항 취소 및 적용

**변경사항 취소**

- 마지막으로 적용한 상태로 복원한다.
- 아직 적용하지 않은 모든 변경사항을 취소한다.

**변경사항 적용**

- 현재 관리자 상태를 실제 게임 모드 구성에 적용한다.
- 자체 정렬 실행.
- 선행 모드 의존성 검사.
- 문제가 발견되면 경고 및 사용자 확인.

## 13. 데이터 구조

다음 클래스를 중심으로 구성한다.

| 클래스 | 역할 |
|---|---|
| ModData | 모드별 관리 정보 |
| CategoryData | 카테고리 정보 |
| TagData | 태그 정보 |
| FolderData | 폴더 정보 |
| PresetData | 모드 목록 프리셋 |
| ManagerSettings | 전체 관리자 설정 |

### 13-1. 데이터 관리 규칙

- PackageId를 유일한 모드 식별자로 사용한다.
- 모드는 하나의 카테고리에만 소속된다.
- 모드는 하나의 카테고리 폴더에만 소속된다.
- 모드는 여러 태그에 소속될 수 있다.
- 태그 내부 폴더는 태그별로 별도 관리한다.
- 태그 삭제 시 모드와 태그의 연결 정보를 정리한다.
- 구독 취소 후에도 관리 정보를 유지한다.
- 신규 모드는 미분류 폴더에 배치한다.
- Core 및 DLC는 보호한다.
- 폴더 이름 중복을 검사한다.
- 폴더 이동 시 이름이 중복되면 병합한다.

## 15. 핵심 구현 원칙 요약

1. 실제 모드 활성화 상태는 PackageId별 개별 상태 하나만 관리한다.
2. 카테고리는 최종 게임 적용 여부를 결정한다.
3. 태그와 폴더는 모드 개별 활성화 상태를 일괄 변경하는 도구다.
4. 태그와 폴더의 ● / ○ / ◐ 상태는 소속 모드 상태를 집계해 계산한다.
5. 동일한 모드가 여러 화면에 표시되어도 활성화 상태는 동일하다.
6. Core 및 DLC는 모든 일괄 변경에서 보호한다.
7. 구독 상태와 사용자 관리 데이터는 독립적으로 유지한다.
8. 빠른 폴더 이동 창은 세 개의 폴더 목록을 나란히 표시하는 3열 구조로 구성한다.
9. 빠른 폴더 이동은 현재 관리 화면과 무관하게 사용할 수 있어야 한다.
10. 모든 데이터 변경은 취소 및 적용 기능으로 관리한다.
